## 5. Assumptions, contract notes, limitations

- **Adopted (T-00):** grade 0–10, pass ≥ 5; AND prerequisites passed in an earlier term; failed course may be retaken; default weights .50/.20/.10/.20; stateless API.
- **Routine choices made by the agent (reversible, review requested):**
  - `goal_match` = max relevance over the student's goals, using an explicit `goal_relevance` map in the catalog.
  - `interest_match` = Jaccard between interests and course topics.
  - `preparation` = share of recommended-preparation courses already passed.
  - Reason texts are in Vietnamese, with thresholds 0.5 (positive) and 0.3 (low relevance).
- **Contract change proposed (not yet in OpenAPI):** `GET /v1/catalog/meta` returns goals, topics and terms. The web client needs these to build the profile form. This is additive and changes no existing field. `/v1/health` is operational only.
- **Additive response fields** not listed in the OpenAPI schemas: `score_percent`, `components`, `reasons`, `unlocks`, `entered`/`exited`, `baseline_digest`. The response schemas allow extra properties, so this does not break the contract, but `openapi.yaml` should be updated.
- **Not implemented (stretch per backlog):** `/semester-plans` and `/roadmaps` return 404.
- Fault injection uses the `X-AI07-Fault` header and works only with `AI07_ALLOW_FAULTS=1` or `create_app(allow_faults=True)`.
- Synthetic data demonstrates logic only; no accuracy, usability or load claims.
