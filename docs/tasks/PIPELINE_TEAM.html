AI-07: Từ hồ sơ
đến đề xuất có giải thích

Sản phẩm giúp sinh viên chọn môn theo mục tiêu và lịch sử giả lập, giải thích điều kiện tiên quyết, rồi thử đổi ưu tiên để xem đề xuất thay đổi.

Đọc nhanh: Tài liệu giải thích hai pipeline: hệ thống xử lý dữ liệu để gợi ý môn như thế nào, và các phần được phát triển rồi tích hợp theo thứ tự nào. Các sơ đồ là thiết kế dự kiến.
01 / AI-07 HOẠT ĐỘNG THẾ NÀO?

Luồng xử lý có nhánh và vòng lặp

Ví dụ: sinh viên muốn làm ML Engineer, đã học Lập trình và Đại số tuyến tính, nhưng chưa học Xác suất.

✓ Có thể học ngay

Xác suất: đáp ứng điều kiện mẫu; phù hợp mục tiêu học máy.

Ranking = sắp thứ tự môn hợp lệ. Điểm là mức phù hợp theo quy tắc, không phải xác suất thành công.

Chưa thể học ngay

Machine Learning: thiếu Xác suất.
Deep Learning: thiếu Machine Learning.

Why-not = giải thích vì sao chưa được đề xuất. Điểm cao không được bỏ qua tiên quyết.

What-ifTăng ưu tiên tải học nhẹ → chạy lại cùng engine → so thứ hạng và lý do trước/sau. Hồ sơ gốc được giữ.
→
RoadmapKỳ 1: Xác suất → kỳ 2: Machine Learning → kỳ 3: Deep Learning, nếu mọi điều kiện khác đều đủ.

Ví dụ minh họa theo catalog mẫu. Chọn môn vào kế hoạch không đồng nghĩa đã hoàn thành môn; còn phải đáp ứng tín chỉ và lịch mở môn.

02 / PHÁT TRIỂN THEO THỨ TỰ NÀO?

Phát triển song song, tích hợp liên tục

Mũi tên liền thể hiện phụ thuộc. Các nhánh có thể chạy song song khi interface đã rõ. Mũi tên nét đứt thể hiện phản hồi: kết quả có thể quay lại yêu cầu, contract hoặc code.

Mỗi vòng có một bản chạy nhỏ để kiểm tra. Backend có thể dùng fixtures khi data chưa xong; web có thể dùng mock API. Khi có implementation thật, phải kiểm tra lại contract và tích hợp. Phản hồi có thể làm thay đổi cả yêu cầu, không chỉ code. Graph UI bổ sung sau graph API; reliability bổ sung và kiểm tra trên luồng tích hợp.

API contract là gì? Là thỏa thuận “gửi những trường nào, nhận những trường nào, lỗi trông ra sao”. Ví dụ: backend trả course_id thì frontend cũng đọc course_id. Chốt trước giúp các agent ghép code được.
03 / CÁC PHẦN NẰM Ở ĐÂU?

Cấu trúc repository

docs/
  architecture/   ← schema, API, thuật toán, quyết định
  tasks/          ← pipeline, backlog, prompt và evidence
src/
  backend/        ← code xử lý và API
  web/            ← giao diện
  prototype/      ← bản thử giao diện đã có
test/             ← kiểm thử backend, web và tích hợp
build/deploy/     ← cấu hình chạy, build và bàn giao
tools/            ← tiện ích sinh dữ liệu / đánh giá

Backend dùng chung bộ quy tắc cho tiên quyết, ranking và explanation. Web hiển thị kết quả API; không tự tạo một công thức chấm điểm khác. Schema và response mẫu giúp các phần giao tiếp nhất quán.
